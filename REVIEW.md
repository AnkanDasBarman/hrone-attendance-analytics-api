# Starter Code Review

| # | Where (function / line) | What was wrong | How to notice | How it was fixed |
|---|---|---|---|---|
| 1 | `health()` | Readiness could report success without confirming MongoDB was available. | Stop MongoDB and request `GET /health`; it must return 503, not 200. | Ping MongoDB and translate driver errors to HTTP 503. |
| 2 | `EmployeeIn` | Employee fields were not all constrained to the contract: employee-code/email formats, string lengths, shift-time format, valid calendar date, and differing shift times. | Submit malformed employee data, an impossible date, or identical shift times; expect 422. | Added Pydantic field and model validation. Overnight shifts remain valid. |
| 3 | `create_employee()` | A concurrent duplicate employee insert could escape as an unhandled database error instead of the contract's 409. | Send parallel creates with the same `emp_code`. | Keep the unique employee index and convert `DuplicateKeyError` to 409. |
| 4 | `create_employee()` response | `created_at` must be an epoch-millisecond integer at the HTTP boundary, not a Python/BSON datetime. | Create an employee and inspect the JSON type and value. | Set it on the server in UTC and serialize it to epoch milliseconds. |
| 5 | `list_employees()` | Employee-list records also needed `created_at` converted to epoch milliseconds. | List employees with `created_at` and inspect the returned values. | Convert each non-null stored value before returning the page. |
| 6 | `PunchInIn`, `PunchOutIn`, `RegularizeIn`, punch handlers | Coercible timestamp types and invalid epoch-millisecond ranges could pass validation. | Try a string, float, seconds-looking number, or out-of-range timestamp; expect 422. | Use strict integer request fields and validate the epoch-millisecond range before conversion. |
| 7 | `punch_in()` | Duplicate attendance inserts for one employee/date must be race-safe and return a conflict, not an unhandled duplicate-key error. | Send simultaneous punch-ins for one employee and attendance date. | Enforce the unique `(emp_code, date)` index and map duplicate-key errors to 409. A concurrency check produced one success and nine conflicts. |
| 8 | `punch_out()` | A completed most-recent record must produce 409, and simultaneous requests must not both close it successfully. | Repeat or race punch-outs against the same open record. | Select the latest qualifying punch-in, return 409 if it is already closed, and use a conditional atomic update. A concurrency check produced one 200 and nine 409s. |
| 9 | `parse_calendar_date()`, `list_attendance()`, `explain_endpoint()` | Attendance date filters needed real-calendar and range-order validation; malformed dates had previously been accepted by the list route. | Try a non-date, `2026-02-30`, or `date_from > date_to`; expect 422. | Parse canonical ISO dates and reject invalid or reversed ranges in both list and explain paths. |
| 10 | `regularize_attendance()` | An explicitly supplied `status: null` was indistinguishable from an omitted status and could be accepted. | Send a PATCH with `status: null` and another otherwise-valid change; expect 422. | Check `model_fields_set` and reject explicit null while allowing the field to be omitted. |
| 11 | `regularize_attendance()` | Concurrent corrections must not silently overwrite another correction or its audit history. | Submit simultaneous changes to the same attendance record and compare successful changes with stored history. | Use a compare-and-swap update including the prior tracked fields and history; a losing request receives 409. A concurrency check preserved one history entry per successful request. |
| 12 | `build_late_leaderboard_pipeline()`, `late_leaderboard()` | Separate pipeline implementations could make the production result and explain plan drift apart. | Compare the normal endpoint's filters/ranking to its explain pipeline. | Use the same helper to construct the normal and explain pipelines. |
| 13 | `explain_endpoint()` | Unsupported explain names returned 501 even though the contract defines a fixed set of supported names and validation errors are 422. | Request `/admin/explain/not_real`; expect 422. | Added an allowlist for the five supported names and return 422 for other values. |
| 14 | `create_indexes()` / department summary explain | The unfiltered department summary filtered by `joined_on` without a supporting index, yielding a `COLLSCAN` on employees. | Explain `department_summary` without a department filter. | Added the `joined_on` index. On a 100,000-attendance-record test database, the unfiltered plan used an index scan and no collection scan. |
| 15 | End of `main.py` | A stale TODO block said implemented endpoints were still unfinished. | Compare the TODO list with the registered routes. | Removed the obsolete block. |

## Inspected and not considered defects

- The punch-out limit rejects durations **greater than** 24 hours. Exactly 24 hours is allowed by the contract, so changing `>` to `>=` would be incorrect.
- The punch-out lookup must select the latest qualifying record even when it is already complete; filtering `punch_out: None` in that lookup would hide the record and prevent the required 409 response.
- An attendance day with no document is not the same as an `ABSENT` document. The analytics distinguish missing records from explicit absence.
- The analytics read stored derived fields such as `late_minutes`, `overtime_minutes`, `work_hours`, and `half_day`, as required; they do not recompute those values from historical punches.
- Regularization records only fields that actually changed and appends to `history`; punch-in and punch-out do not create audit entries.
